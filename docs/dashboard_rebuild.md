# 看板重建记录

记这一版 `dashboard/` 推倒重建的过程、量到的数、以及**没能做到的部分**。写给自己和接手的人看，
不是交付文档；用法与每页读什么列见 `dashboard/README.md`。

## 一、重建前的问题

上一版七页是同一套模板的七份拷贝：一个页标题、一行筛选器、一组页签，每个页签里
「一张图 + 一段说明 + 一个折叠块」。全仓库 14 个折叠块**标题全都叫「表格视图」**，
读者展开之前不知道里面是什么；页面里没有一处 `st.title`。外观则基本是 Streamlit 的出厂样，
`[theme]` 的 48 个配置键只用了 4 个，唯一的自定义样式是一段内联 HTML。

## 二、重建后的样子

页还是七页，但按**问题**分而不是按图分：概览与业务结论 / 数据与因子概览 /
VaR 模型对比与回测 / 模型诊断与验证 / 压力测试交互分析 / 稳健性检验与数据质量 /
结论分级与已知边界。每页的骨架现在是四件原生组件：

- `page.header()` 页头，带口径与数据区间两枚元信息
- `page.kpi_row()` 一排 `st.metric(border=True)`，标签写的是一句判断而不是名词
- `page.card()` 图卡，`st.container(border=True)` + `st.subheader()`，卡里是图、
  一句读法、和一个**标题写得明明白白**的数据抽屉
- `page.footer()` 页脚，写明本页读的是哪几个 CSV 的哪几列

**代码里没有一行 CSS。** 颜色、圆角、边线、字体全部落在 `.streamlit/config.toml` 的
`[theme]` 里，右上角的 Deploy 按钮与开发者菜单用 `[client] toolbarMode = "minimal"`
这个原生开关关掉，不是用 CSS 去藏元素。`lib/style.py` 随之删除，`tools/check_dashboard.py`
里加了一条断言：它若复活就算失败。

## 三、路上抓到的一个真 bug：分面图撑破容器

这一版最值得记的一处，因为它**在 Python 侧一声不响**。

分面的 Vega-Lite spec 里，顶层的 `width` 是**每一格**的宽度。Streamlit 在
`_prepare_vega_lite_spec` 里对分面图设了 `autosize = {"type": "pad", ...}`，又把
`use_container_width` 的宽度应用到**每一格**，于是 k 格的图画出 k 倍宽，从卡片里溢出去
盖住右边那一栏。实测溢出 86～1579px，横跨第 2、4、5、6 四页共 12 张图。

修法是在 `lib/charts.py` 里加 `facet_width(columns)` 定死每格宽度，并配
`st.altair_chart(..., use_container_width=False)`。`width="container"` 治不了这个——
它在分面 spec 里同样是每格的宽度。

`tools/visual_check.py` 现在把这条做成了常驻检查：量每张图 SVG 的宽与它容器的宽，
超出 8px 就报。

顺带记一条 Altair 5.5 的坑：`FacetChart.columns` 是属性不是方法，`.columns(2)` 会抛
`TypeError: 'UndefinedType' object is not callable`。要折行得用简写形式
`facet(alt.Facet(...), columns=2)`。

## 四、页高：量到的数，和没做到的部分

重建时我给自己定了个「压到 1～2 屏」的目标。**这个目标没达到，而且我判断它对这批页面
不成立。** 实测（1600×1000 视口，全页高）：

| 页面 | 图 | 读数卡 | 重建前 | 重建后 |
|---|---|---|---|---|
| 概览与业务结论 | 0 | 4 | 1.6 屏 | 1.6 屏 |
| 数据与因子概览 | 13 | 4 | 3.5 屏 | 3.2 屏 |
| VaR 模型对比与回测 | 8 | 8 | 4.1 屏 | 3.9 屏 |
| 模型诊断与验证 | 7 | 4 | 3.4 屏 | 3.2 屏 |
| 压力测试交互分析 | 5 | 4 | 2.5 屏 | 2.5 屏 |
| 稳健性检验与数据质量 | 8（另 4 张在页签里） | 4 | 3.5 屏 | 3.2 屏 |
| 结论分级与已知边界 | 2 | 4 | 1.5 屏 | 1.5 屏 |

跑了一轮压缩（把长题注整句搬进同一张卡的数据抽屉 note、把与抽屉重复的内联表下沉），
四页各拿回 200～310px，约 8%。再往下压不动了，原因是量出来的两条：

**其一，页高是「每行取两张卡里较高的那张」，不是元素高度之和。** 把矮的那张卡里的题注
挪走，对页高是 0 收益。第 3 页实测五行的高度分别是 465 / 552 / 590 / 347 / 669，
较高那一侧主要是 8 张图（约 1984px，图高 240～280 已定死）与 8 张读数卡（约 796px）。

**其二，我最初那张构成表算错了。** 我写的「内联表占 2260～2760px」不成立——那是我用
`getBoundingClientRect` 量的时候**把收在数据抽屉里的表也算了进去**，而收起的抽屉不占页高。
四个页面顶层真正只有 `st.dataframe` 2 / 4 / 0 / 2 张，其中第 3 页的评分卡与定案表是
核心交付物，不能删。所以「表格下沉」这条路几乎没有余量。

要进 2 屏只能删图或删读数，那是删内容，不是压缩。所以 `tools/visual_check.py` 的页高
护栏定在 **4.0 屏**，并在代码里写明它是「别再滚个没完」的回归护栏（重建前这几页是 4～6 屏），
不是版式目标。

## 五、这一版验了什么

- `tools/check_dashboard.py`：七页 AppTest 逐页零异常，44 个数据抽屉**标题互不重复**，
  每页有原生页头与读数带与页脚，页面源码无 emoji、无 `unsafe_allow_html`、无已废组件。
- `tools/visual_check.py`：真的起 headless Chrome 逐页渲染，量几何、留截图。
  七页全部通过——无空图、无溢出、无 Streamlit 外壳泄漏、页高在护栏内。
  带页签的第 6 页另外点开三个页签各量了一遍（最高的是默认页签 3.2 屏）。
- `tools/check_palette.py`：配色五项检查与 config/令牌对账全过。
- `code/check_outputs.py`：26/26 产物一致；`git status` 在 `results/ figures/ clean_data/
  factors/ events/` 上为空，看板只读契约成立。

## 六、已知限制

- **观感只能由人定夺。** 上面这些脚本能证明「画出来了、没串位、没裁切」，证明不了「好不好看」。
- `visual_check.py` 只量默认页签，带页签的页面要人工点开复核（第 6 页已复核）。
- 第 3 页那八张读数卡是两行，占了约 796px。这是全仓唯一一处成规模的、能靠减法拿回页高的
  地方，但减它就是删读数，没有你的话我不动。
- `docs/phase3_scenario_library.md` 里有一处前后不一致：第 121 行写 `doas_bp`
  「序列自 2023-09-05 起」，同一份文档第 329、464、469、473 行都写 2023-09-06。
  数据侧是对的（`oas_bp` 起 2023-09-05，`doas_bp` 是它的一阶差分、首日无差分可算，
  起 2023-09-06）。那四条窗口都在 2022 年，结论不受影响，只差一天。
  这几份周报是已交付件，我没擅自改。
